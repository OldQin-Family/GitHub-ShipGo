# 端到端成品示例 · 把 PebbleLog 发到能发

> 这是评测里"缺从零开始的完整成品示例"那一项的补齐：用一个**虚构小工具**，把 GitHub-ShipGo 的三站式从拿到项目一直走到"拿到就能发"。
>
> **示例台架**：`demo-project/` 里的 **PebbleLog（鹅卵石笔记）**——一个只往本地文件追加一行笔记的命令行小工具，只用标准库、不联网。它是为演示而生的虚构项目，不是真实产品。
>
> **本页所有命令输出都是在 `demo-project/` 上真实跑出来的**，件数与哈希由探针实算，不手编。你可以照着原样重跑。

---

## 0. 起点：你手上有什么

一个刚做完的小项目，长这样：

```
demo-project/
  pebblelog.py        本体（记一条 / 列出全部）
  test_pebblelog.py   最小自测
  README.md           一句话说明（还没按发布版式规整）
```

没有 LICENSE、没有 NOTICE、没有英文版、没有发布约定——这些正是 skill 要帮你补齐的。

---

## 1. 第⓪步：先体检（不过不开工）

开工第一动作永远是预检，不是写文档。四脚本各跑 `--selftest`，探针走 `--check`：

```bash
python -B -I -X utf8 scripts/en_acceptance_check.py --selftest
python -B -I -X utf8 scripts/restyle_readme.py --selftest
python -B -I -X utf8 scripts/checklist_check.py --selftest
python -B -I -X utf8 scripts/text_quality_check.py --selftest
python -B -I -X utf8 scripts/fingerprints_scan.py . --check
```

> 注意两条铁规矩：**探针没有 `--selftest` 开关**（照抄必报错，它走 `--check`）；所有命令统一带 `-B`（不写 `__pycache__`，否则第一条命令就把包弄脏、紧随的 `--check` 判净空违例）。
> 预检各条『→』读数都落盘，全绿才进站一。

---

## 2. 站一：问卷，把约定定下来

skill 先替你"把话说一半"，再逐个问清必答三项。对 PebbleLog 这段对话长这样（话术逐字见分册④）：

- **项目干什么** → "我读了一下，这像是个往本地文件记一句话的小工具，能帮人快速记笔记——我理解得对吗？" 你点头，约定写下"本地单行笔记"。
- **版权** → "建议用 MIT——别人能免费用、随便改、还能再发，只要留着你的名字。" 你说行，回执一遍人话翻译。
- **名字与平台** → "GitHub 搜同名仓库 0 个、PyPI/npm 查无此包；域名商店算'未发现'，不等于绝对没有。名字就叫 PebbleLog 吗？仓库还没建？没关系，先把发布件做出来，地址后补。"

选答项（README 开头要不要放自己的话、有没有一个字都不能改的承诺、测试跑过没有、署名、要不要英文版）一次只问一个，答完落盘。

**产物**：`_过程件/发布约定.md`——字段一个不能少，必答跳过的写"未问"、选答跳过的写"默认"。

---

## 3. 自动段：skill 一口气做发布件（零打扰）

这一段不打扰你，唯一会打断的情况是"不拍板就只能编数据或删功能"。它按顺序做：备素材 → 中文 README → 英文版＋验收 → 美化 → AI 四件套 → 收口 15 项。

其中**测试实跑**是硬闸。PebbleLog 的自测真跑结果：

```text
$ python -B -I -X utf8 -m unittest discover -s . -p "test_*.py" -v
test_add_then_read (test_pebblelog.TestPebbleLog.test_add_then_read) ... ok
test_empty_file (test_pebblelog.TestPebbleLog.test_empty_file) ... ok

----------------------------------------------------------------------
Ran 2 tests in 0.003s

OK
```

**功能也真跑一遍**（记两条再列出，演示数据跑完即清）：

```text
$ python pebblelog.py "把发布流程跑通"
已记下 → …\notes.txt
$ python pebblelog.py "示例第二条"
已记下 → …\notes.txt
$ python pebblelog.py
把发布流程跑通
示例第二条
```

> 收口 15 项逐项读数落 `docs/收口检查单.md`，英文版"一出一验"落 `docs/英文验收单.md`。人判项（口径三律、红线逐字、中英一致）由**另一双眼睛**签，做的人不给自己验收。

---

## 4. 收尾：指纹账实算

发布件齐备后，探针对 `demo-project/` 实算，生成 FINGERPRINTS 表行——**这是真实输出，不是示意**：

```text
| 文件 | 字节 | SHA256（前 16） |
|---|---|---|
| `README.md` | 490 | `9B7A85F2A391C10D` |
| `pebblelog.py` | 1,260 | `06939416C3487294` |
| `test_pebblelog.py` | 654 | `772EAC74AC11BAD1` |

# 实物件 3 件（FINGERPRINTS.md 自身不入表；含分发 zip 0 个，其 zip: 内件为虚拟行不计实物）
```

> 这是台架原始三件的账。真实发布时还会加上 LICENSE／NOTICE／英文版等发布件，件数随之增加；改任何一件后**只重算受影响行**，再 `--check` 至"表盘一致"。

---

## 5. 站二核对 → 站三交付

- **核对两问**："名字、署名、介绍的话、语气，你看看有没有要改的？" "这次的活到这儿算齐了吗？——**你说了算**。"
- 你多问一句"多出来的件是干什么的"，就一件一行给你讲清（FINGERPRINTS＝封条、site.json＝给 AI 的目录页、llms.txt＝给 AI 的路牌……）。
- **清理逐件列单**，你确认才动手；封包在放行后重扫指纹、`--check` 表盘一致才封死。

**结束报告四段**：做了啥／缺啥／咋补／哪些等你拍板。PebbleLog 这单会如实写——"真机截图没有，以实跑输出渲染图替代""查重只到 GitHub/PyPI/npm，域名商店算未发现""英文版 A5 红线对照待人判签"。skill/仓库克隆类项目如不打分发 zip，单列为 N/A 并指向 FINGERPRINTS 的结构化立牌，不写进"缺啥"。

最后一句边界永远不变：

> 发布包就绪了。接下来是发布环节——**这是你的主场**：什么时候发、发到哪个账号，都由你定。

---

## 你能拿这个示例干什么

- **照着走一遍**：把 `demo-project/` 换成你的项目，命令几乎不用改。
- **看懂每道闸长什么样**：tests 实跑、指纹实算、验收单留痕，全是真输出。
- **知道哪步会问你**：只有站一的必答三项、素材缺口、站二的两问会打断你，其余零打扰。

> 本页是"怎么走"的成品样例；各道闸的完整判据仍以分册①②③④为准，常见报错翻 `references/FAQ常见问题.md`。
