# FAQ · 常见问题与排障

> 把散在各册的"报错了怎么办／为什么会这样／能不能绕开"收口到一页，按使用顺序分六类。
> **每条都短：现象 → 原因 → 怎么办**。判据的完整表述仍在各分册，本页只做指路，不替代判据。
> 找不到你的问题？先按"预检"重跑一遍，多数报错在预检就会现形。

---

## 一、环境预检（第⓪步）

**Q：跑 `fingerprints_scan.py --selftest` 直接报错？**
探针**没有** `--selftest` 开关，照抄必报错（exit 2）。它走 `--check` 对实物目录校验，行为自检由"四工具联检"承载。四支带 `--selftest` 的脚本是 en/restyle/checklist/text_quality。→ 见分册③ §2.1。

**Q：`--check` 一跑就判"净空违例"？**
预检第一条命令若没带 `-B`，会先生成 `__pycache__`，紧随的 `--check` 就把这些运行期残留判成违例。**所有脚本统一带 `python -B -I -X utf8`**，再清掉已生成的 `__pycache__`／`*.pyc` 重跑。→ 见分册③ 第 15 项。

**Q：预检吐"python <脚本>"，照抄却挂（如 exit 49）？**
`python` 不一定在 PATH。预检会打印 `sys.executable` 的**本机实测路径**，以它为准，别假设 `python` 可用。→ 见分册② §2.1。

**Q：stdout 是空的或乱码？**
别反复重试回显。落文件再读：`python xxx.py > out.txt 2>&1`，读时显式 `encoding="utf-8"`。→ 见分册② §2.1。

**Q：体检被宿主环境拦（子进程被拦截、某类命令被限制）？**
先分清是哪一层：skill/脚本本身的问题→按判据处理、不过不开工；宿主环境层受阻→**节点照走、读数如实立牌、不装过、不空等**，能绕的照跑，交付站"缺啥"段如实报告。分不清按保守侧（停手问用户）。→ 见分册④ §2.1。

**Q：当前宿主禁止 `-I` 隔离参数，selftest 起不来？**
en_acceptance 与分册③联检会先按统一参数 `-B -I -X utf8` 尝试；若宿主明确抛 `PermissionError`，会打印 WARN 并降级为 `-B -X utf8` 重跑，保留“不写缓存”。这是宿主兼容路径，不是脚本假红，也不要求所有宿主都复现该限制。

## 二、问卷站（站一）

**Q：查重查不动（GitHub/PyPI 打不开或超时）？**
不许装查到了，也不许静默跳过。**声明假设＋记录方法与结果＋复搜时机留档**；能请用户自己开浏览器搜一下就把结果告诉你。查不到＝"未发现"，不等于绝对没有。→ 见分册① §0。

**Q：用户说"能自己弄的自己弄／你看着办"？**
授权省事**不免除必答项与素材确认**——必答 3（项目干什么／版权／名字与平台）和素材缺口照常问到，可以合成一句问、带默认，但不许整题跳过。真跳过的在《发布约定》该项写"未问"，下轮补。→ 见分册④ §1.6.1。

**Q：项目没有图标和截图，怎么办？**
三路都通：实跑程序拍真实输出图（绝不修饰）／用户自己供图／干脆不要图。截图必须是真跑输出，不补没出现过的字，不用别人现成的图。**必选件不许拿占位图充数**；CLI 类项目以真实运行输出的渲染图视同截图。→ 见分册④ §1.7、分册① §1。

## 三、README 美化（自动段④）

**Q：restyle 首跑 exit 1？**
"首跑 exit 1 属预期"是**旧码**的绕行口径，已作废。干净 README 首跑应 exit 0——管道注入的标准节（目录/截图/流程图）属预期注入，记显式降级声明、不判 FAIL。只有**重复注入**（同名节 >1）与**未配置注入的节**才判 FAIL。→ 见分册② §4。

**Q：改完版式发现链接/图片断了？**
美化只动版式，但版式操作可能弄断链接。**美化后重新走一遍分册② §3 的检查**。→ 见分册② §4。

**Q：对英文文档跑中文 config？**
会触发 restyle 语言混杂降级警告＋ en_check A4 CJK 残留 FAIL。**英文版美化须另备英文 config**（`section_titles`／`badges`／`caption` 全英文）；`site_line` 需要前缀时显式给 `text` 键，缺省不加前缀，不会自动塞中文。→ 见分册② §4。

**Q：单独把 restyle_readme.py 拷去用，报 ModuleNotFoundError？**
它从同包 `en_acceptance_check.py` import 豁免表，**两脚本必须同包成套分发**，单独跑会摔（符合设计意图）。别照旧参考抄独立件。→ 见分册②附 开头。

## 四、英文验收（自动段③）

**Q：A5 红线句对照为什么不在机器跑的 A 类里？**
英文版"逐字对照"物理不成立（中文全角标点带不过去）。A5 归入 **C 类人判**：①红线承诺逐项语义对齐（每条承诺在英文版有对应句且无弱化）＋②terms 定译词在对应句命中，两条齐才算过。**机器项 A1–A4 跑过不代表 A5 过**。→ 见分册② §3.3。

**Q：术语表 grep 整篇误报？**
三查：①**定译本身别进禁用列表**（只禁旧译，定译塞进去＝整篇误报）；②**禁用旧译别与代码字面量冲突**（如禁 whitelist 时代码里真有 whitelist.json，冲突就降级为"正文概念禁用、字面量豁免"并写进备注）；③**值必须是字符串数组**——写成字符串会被 extend 按字符拆成单字母，整张验收单作废。→ 见分册② §3.1。

**Q：英文版冒出中文标题/图注？**
那是 A4 CJK 残留检测命中。豁免口径＝`allow_literals`＋代码块/行内代码＋**资源目标路径**（markdown `](…)`／HTML `src="…"`，含 `assets/截图/` 这类中文目录名）＋语言切换锚/署名预置豁免。真内容中文要改掉。→ 见分册② §4。

## 五、收口与指纹（第⑥⑦步）

**Q：FINGERPRINTS 件数对不上（61/62/63 各有说法）？**
是**统计口径**问题，不是坏包：磁盘实物件数含 `FINGERPRINTS.md` 自身，而**账自身不入表**，探针 `--check` 的"盘点实物"与"表行条目"又是两个口径（表行含 zip: 虚拟行）。以探针 `--check` 结论"表盘一致"为准，别拿三个数字互相对。→ 见分册③ §2。

**Q：补列 FINGERPRINTS 进 site.json 后 `--check` 又出入？**
补列动作本身改了 site.json 字节——**必须重扫并更新 site.json 的指纹表行**，再跑 `--check` 至表盘一致。只"复验孤条"不重出指纹＝表行哈希过期。→ 见分册③ §1 第 2 项。

**Q：分发 zip 什么时候打？**
应用类项目在**⑥其余 14 项过闸之后**——过闸→冻结→打 zip→才验第 12 项。zip 打完后源码/tests/工作副本 README/LICENSE 任一件变更＝回到⑥重走，不许先打 zip 再补过闸。skill/仓库克隆类可不打，但必须在 FINGERPRINTS 的「条件件 N/A 立牌」专节精确登记；只写散文不豁免。→ 见分册③ 第 12 项、分册① §3。

**Q：能在成品位加 `--dev-archive` 吗？**
不能。留档对拍格是**开发期专属闸**，成品位结构上没有 `_历史` 与开发账，显式开启会 FAIL 并点名缺账。开发期请在副本按分册③ §1 样例建账后开启。→ 见分册③ §1。

**Q：组装 FINGERPRINTS.md 能用 shell heredoc 拼吗？**
不能。反引号会被 bash 当命令执行、`\t` 等转义会被吃。**一律用 Python 写文件**（`Path.write_text`）。→ 见分册③ §2。

## 六、交付与边界（站三）

**Q：AI 能帮我直接发到 GitHub 吗？**
本 skill **只前置不介入**：做到"拿到就能发"为止，**不代开仓、不代上传、不代发版**。发不发、什么时候发、发到哪个账号由你决定。清理与封包的触发权也在你——AI 不自判"做完了"。→ 见 SKILL.md 交付边界、分册④ §3。

**Q：能跳过三站式、一口气无人值守跑完吗？**
**免交互直通未实现，不要承诺**。本版三站式是唯一路径：问卷定约定 → 自动段做发布件 → 核对交付。→ 见 SKILL.md。

**Q：这工具能部署我的网站上线吗？**
不管。本 skill 管**代码仓库发版与发布包收口**，不管网站部署上线。→ 见 SKILL.md frontmatter 边界。
