## 二、历史判例（每条判据背后的真实踩坑）

> 这些"实案／早期某轮"是判据的来源证据。正文不再逐条夹叙，统一记在这里。

- **输出件判据**：曾有 33 个自制脚本零输出留痕、自报四类 PASS 全无盘证的实案——故"每个闸口过闸＝盘上有对应输出件"，没有输出件的闸按未过处理。
- **编码铁律**：`-I` 会屏蔽 `PYTHONIOENCODING`，曾导致证据乱码；故调脚本统一 `python -B -I -X utf8`（`-X utf8` 不受 `-I` 影响；`-B` 免生 `__pycache__`，否则第一条命令就把包弄脏、紧随的 `--check` 必判净空违例）。stderr 重定向落盘后读文件要显式 `encoding="utf-8"`（Windows 重定向默认 ANSI）。
- **落证据禁走 Out-File 管道**：`python xxx.py | Out-File -Encoding utf8` 在中文 Windows 上 PowerShell 先按 ANSI 解码子进程输出，`-Encoding utf8` 救不了已坏的字节——踩过两次。子进程 stdout/stderr 直接以二进制落盘。
- **单人执行降级**：B 类人判项"物理上无法找到第二双眼睛"时，降级为"首次出现加括注＋对照翻车实录自检"并挂"待第二双眼睛"，不装全验过。
- **升版清单**：曾有升版零判据、tests 版本断言写死旧版号的实锤——升版本号先 grep 再动手（VERSION 常量／tests 断言字面／素材文件名版本段／CHANGELOG＋README／site.json·llms.txt·SKILL.md）。
- **尺寸指纹两段核**：⑥过闸时 FINGERPRINTS 尚未生成，"与表一致"无法执行——故拆 10a（⑥与素材库原件比）／10b（⑦与表行复算）两段。
- **site.json 孤条豁免**：⑤步列 FINGERPRINTS 必孤条——⑤暂不列或列后孤条检查豁免，⑦生成后补列并复验归零；补列本身改 site.json 字节，**必须重出指纹**再 `--check`。
- **标点全包口径**："同一文档还是全包"曾有两读——定为**整个发布包统一**，照抄块形态优先，自写文书向它看齐。
- **散放过程文书同禁**：曾有收口检查单/修复单散放发布包根目录自判 PASS 的实案——根层只允许交付实物，过程文书一律移回工作区。
- **依赖前提先核对**：三代未修的信号以更高成本回来——跑 tests 前先核对依赖（如 `psutil` 可选依赖），缺失＝部分用例 error。
- **README/文书改动后必重跑 tests**：tests 会反向校验文书内容，曾有漏码表被 test FAIL 逮住的实案。
- **"我拷了"≠"拷对了"**：留档对拍格断言语义（账载源版本终值），不替代"先 cp 再改"人工动作，只让忘/错当场 FAIL。
- **判据能力匹配**：曾有"注入后必重跑英文验收"但 en_check 当时无 CJK 检测——照判据走照样放绿。每轮复核要查"判据让你跑的那道闸真能逮住它说的风险吗"。
- **豁免口径相容**：check_cjk 豁免只认反引号曾把合法 `assets/截图/` 路径全逮住；restyle 语言警告无署名豁免被强制署名收尾压死恒不触发；en_check selftest 从不进 main() 致无 `--terms` 崩溃无人测——新闸落刀当场要拿真发布件跑"该放的过、该拦的拦"。
- **selftest 夹具纪律**：三个新 selftest 用例全挑"能过的形态"，回归全绿指纹全对而三层里两层在真件上是死的——夹具必须取册子规定的产物形态或真发布件片段，不许自造理想最小件。
- **探针无 `--selftest`**：旧文"并跑 --selftest 机械校验"是跑不通的命令（实跑 exit 2）。探针行为自检由四工具联检承载。早期⓪步写"四脚本各跑 --selftest"字面照抄必踩空（双源实锤）。
- **嵌码转义**：md 代码块嵌 python 的转义层数曾写岔（反斜杠两枚写成四枚；嵌码里 `\n` 手滑成真换行）——md 不转义代码块、只写 python 字面形式，嵌码必经"提取→实跑"验证。
- **探针只验表内不验漏登记**：删 5 行登记照样 exit 0——探针 v2 加反向对拍＋宽松认领＋总件数对账，删行/孤件两用例必跑。
- **出表与 --check 不接头**：照册字面填必踩——scan 直接吐管道表行，两模式接头。
- **哈希只比前 8 位**：第 9 位改错照样 PASS——表存全长就比全长。
- **册说 X 码说 Y**：册子写"九步"代码实为另一组九步——册码步骤清单逐一对表。
- **整形器插入点**：流程图插在标题行正后方、截图落错段——插入点＝"整节之后"，验骨架顺序。
- **头像全局替换误伤**：非头像行被改、verify 没实现宽度例外（输入 120 自炸）——行级替换＋认任意宽度＋例外落进 verify。
- **verify 集合匹配**：不防重复行删除/乱序、未授权第四例外——多重集＋顺序感知，例外全部显式写进册与码。
- **工具只在顺手目录跑**：`ZipFile(r)` 在目标目录内全绿、换目录即崩——工具验证必须换目录跑一遍。
- **字符类转义不闭合**：`[\]` 不闭合 `]` 致正则对任何输入都不匹配；拿"成品长相"当路径验证——正则当场 compile＋正负例三测，验证断言必须区分走了哪条路径。
- **heredoc 转义**：白名单路径 `\t` 被 heredoc 转义吃掉；正文反引号被 bash 当命令执行——用 Python 原生字符串写文件，不用 shell heredoc 拼正文。
- **argparse 接管**：v3 及之前错误输入（--help/拼错路径）被当目录参数静默吐空表 exit 0——错误伪装成功比报错危险。
- **__pycache__ 静默排除**：原先留在 EXCLUDE_DIRS 使特判不可达、G16 场景静默 exit 0——升格为"净空违例"点名，只能数出来，不靠习惯推断。
- **册内活命令扫描自指**：判据/验法写进被扫对象必自命中——搜索串拼接构造防自指，验法只活在联检里、册子只引用格名。
- **件数 vs 件名**：件数对、件名错照样漏——断言改件名集合（必需件必须都在），新增册不误报。
- **留档格目录筛选**：名字代理/时间代理/扩展名代理都是拿形态当语义——格只断言语义（mtime 最新子目录＋源版本语义断言）。
- **短名映射缺项**：映射表缺 restyle 致留档键位静默丢失（"留档 4 件"假绿比对面缺一件）——读数要内容不要布尔。

## 三、为什么这么改（v3.0.3 说明）

SkillHub 评测指出分册③"工程记录多、内容庞杂"，拉低渐进式披露与结构清晰两项得分。本版把**判据**与**判据的出处**分层：正文＝怎么做，附录＝为什么。**实质判据一条未删**，只是把追溯编号与历史叙述从执行动线上挪开，让新读者（尤其弱模型执行者）不必先读懂一部编年史才能动手。
