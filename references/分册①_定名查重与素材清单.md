# 分册① · 定名查重与素材清单

> 对应三站式流程的站一（定名）与自动段备料。**没查重名不开工；清单没打勾不进整理期。**

## §0 定名与查重（站一）

| 查什么 | 怎么查 | 过判据 |
|---|---|---|
| GitHub | 站内搜项目名＋英文名 | 无同名或语义可区分 |
| Gitee | 站内搜 | 同上 |
| PyPI | pypi.org 搜（Python 项目必查） | 无同名——装包命令冲突即改名 |
| npm | npmjs.com 搜（Node/插件项目必查） | 同上 |
| 域名/商店 | 常用域名后缀＋应用商店搜 | 无冒用风险 |

- 中英文名都查（英文名是重名重灾区）；查重面：**GitHub / Gitee / PyPI / npm / 域名与商店**（五类）；
- **查重兜底**：实查受阻是常态（Cloudflare/渲染/网络）——查不到＝**声明假设＋记录
  方法与结果＋复搜时机留档**，不许静默跳过也不许装查到了；能用公开 API 点名实查就用（
  四类 API 实查零命中也算"查过"）；
- **用户拍板定名后**才进备料——名字是发布件（README/仓库/包清单全用它）；
- 定名时同步拍：仓库描述（按实际功能写，规划项不进描述）。

## §1 发布构成总清单（自动段备料）

**打勾规则**：每件标 `[必选] [条件] [建议]`。条件件的触发条件写明，不触发就写"N/A＋原因"。

**清单元规则（对外版总原则）**：**这份文档用户自己能不能写出来？**
- **能写的**（只有用户才有的话，比如"你为什么做这个项目"）→ **AI 问用户要**，不代编；
- **写不出来的**（NOTICE／隐私说明／CHANGELOG 这类格式与合规文书）→ **skill 全包**，用户不用操心。
> 行家视角的清单是**最小集**；对外版清单是**小白视角的健全集**——分叉就在这条元规则：用户搞不定的，都在这里替他了。

### A. 根件（对外文书）

| 件 | 级别 | 要点 |
|---|---|---|
| `README.md` 中文对外版 | 必选 | 分册② 版式七段；口径三律 |
| `README.en.md` 英文版 | 必选 | 中文版定稿后译，**英文验收单 PASS**（分册② §3）；存量项目可在下次版本迭代时补齐 |
| `LICENSE` | 必选 | 默认 MIT；版权主体按项目实际（未定则用 `Project Maintainer` 占位并立牌） |
| `CHANGELOG.md` | 必选 | 版本链＋Known issues 如实带走 |
| `NOTICE.md` / `NOTICE.en.md` | 必选 | 借了什么/原创什么/LICENSE 三块结构；**中英两份内容对齐**（同一事实、同一名单，不做一增一减） |
| `ACKNOWLEDGEMENTS.md` | 条件 | 研究期读过 ≥3 个参考项目时必做，逐条留痕"未包含其代码" |
| `SKILL.md` | 必选 | AI 运行时手册；铁律＋最短路径＋红线 |
| `llms.txt` | 必选 | AI 读者入口：先读什么/文件表/版本事实/边界 |
| `site.json` | 必选 | 机器可读清单；pages 指向的文件必须真实存在（孤条=缺陷）；**最小集与格式判据见分册② §5（正文七段各一页＋发布件表一页＋使用说明一页，list[dict] 形态）——此处口径以分册②为单一真源，两处不许各自表述；"一页"＝一条目不是一种文件，同一文件可挂多条 role** |
| `index.html` | 建议 | 静态主页，挂 AI 四件套 alternate 链接 |
| `使用说明.md` | 建议 | 给人的短路径：安装/命令/文件地图 |
| `隐私与合规说明.md` | 条件 | **触发判据（人话）**：**这个程序会产生或处理用户的任何数据吗（日志/配置/文件）？——会 → 本件必做；否 → N/A＋原因。** 写法＝三段大白话定心页：**存哪**（你自己指定的文件里）／**谁可见**（谁也看不到，作者也看不到）／**怎么删**（随时删文件就行）。**这是发布件的内容要求**，不是合规话术腔；全包内已有一份的，按本判据重新生成、不手改原件 |
| `FINGERPRINTS.md` | 必选 | **收尾阶段生成**——缺件核查对本件豁免（分册③ §1 已注） |
| `.gitattributes` / `.gitignore` | 必选 | 行尾归一（CRLF/LF）＋忽略缓存产物 |
| `启动<项目>.bat` | 条件 | Windows 直跑类必选；纯 ASCII＋CRLF；py→python 兜底。**命名口径**：仓库内中文名可用；主件"Release 资产纯英文"只管**上传到 Release 的资产**——两处不冲突，别拿 Release 规矩改仓库内文件名 |
| `icon.png` | 必选 | 96px 显示用；项目自备 |

**隐私说明三段式模板（发布件正文，照这个语气写）**：

```markdown
# 隐私说明

这个工具不联网，也不偷偷收集任何东西。

- **你的数据存在哪**：全部存在你自己指定的那个文件里，程序只写这一个文件。
- **谁能看到**：只有你。作者看不到，也没有服务器替你看。
- **怎么删**：把那个文件删掉就行，删了就没了。
```

> 三段之外可以按项目补一句（比如"程序不读注册表、不进后台"），但**三段一条不能少**；
> 红线承诺（如"绝对不联网"）**逐字**进 README，与本页互为表里，不互相替代。

### B. 代码件

| 件 | 级别 | 要点 |
|---|---|---|
| `本体代码` | 必选 | **对外净化检查**：真实路径/内网 IP/厂商名→Example＋RFC 5737。源码扩展名白名单：py/js/ts/go/rs/java/c/cpp/cs/rb/php/sh/ps1 等常见源码后缀均算（审查修正，任意语言项目不冤判） |
| `tests/` | 条件 | 有测试必带，净化后**实跑全过**才算数 |

### C. 包体两件（发版必备）

| 件 | 级别 | 要点 |
|---|---|---|
| `packages/<渠道>-<name>/` | 条件 | **目标渠道要求插件包时必带**。三件套：渠道清单文件（`repository`=实际仓库逐字一致）＋渠道补丁文件＋`lib/`。**断链校验**：清单文件的 `main` 与 `exports` 指向的路径必须**真实存在**（实测实案：源平铺丢 `lib/` 层，照抄致 main 指向空目录断链）。**源平铺时按 `main`/`exports` 路径补层**：落位照 `main`/`exports` 的目录结构补齐层级，**补层后必跑断链校验**。插件可选不碍本体；版本与本体分开走；不自带 LICENSE |
| `分发 zip` | 必选（skill/仓库克隆类可 N/A） | 应用类：源码＋工作副本 README＋tests＋LICENSE；**zip 内不带外链动图**；CRC 全验；件数固定入表。**skill/仓库克隆类项目＝N/A（分发形态即仓库本身），须在 FINGERPRINTS 的 N/A 立牌专节精确登记** |

> zip 内 README 与仓库 README 是**两个版本**：zip=落码工作副本（无图床外链），仓库=对外版（美化＋截图＋流程图）。FINGERPRINTS 里立牌写清，不是错。
> **工作副本在仓库内的位置与命名**：
> 官方口径＝`docs/落码说明.md`（内容＝工作副本 README，厂商名泛化立牌随件；tests 断言用的工作副本仍在 zip 内原名原文）。
> 项目有充分理由改名/移位时**允许，但必须 FINGERPRINTS 立牌**写明"落码说明实际位置＝X＋改动原因"——
> 不许静默自定（三家分别自定 docs/、`_zip_src\<项目>\`、`_过程件\zip_stage\` 三种位置＝缺口实证）。
> **文档断言型项目例外**：
> **搬移前先 grep tests 的 README 断言基准**（例：某项目测试读根 README 断言落码细节）——
> **tests 读哪个位置的 README，断言基准事实句就保留在那个位置**（tests 是断言基准，动了它收口必红）；
> `docs/落码说明.md` 只作**归档副本**，不替代断言基准位置。没有文档断言型测试的项目才按 docs/ 口径走。
> **对外版落点冲突**：文档断言型项目里，"根 README.md＝中文对外版"与"工作副本留 tests 断言基准位置"**可能互斥**
> （tests 读根→工作副本占根→对外版无处放，且 checklist 只查存在性逮不到）。
> **默认动作（无需人即可走且不踩 tests——零提示/不提问语境的出口；交接单未明示"对外版不得含事实句"即按默认走，无需停机）**：
> **根 README 承载对外版式＋tests 事实句（事实句留根，完整工作副本归档 docs/）**——
> 根 README 同时承载对外版式与 tests 要求的事实句（**事实句不删、tests 保持绿**），`docs/落码说明.md` 仅归档；
> 默认路径写成可复算步骤：①根 README 按对外版式写＋保留 tests 断言的全部事实句（先 grep tests 拿清单）→
> ②`docs/落码说明.md` 归档完整工作副本→③收口前实跑 tests 确认绿→④FINGERPRINTS 立牌"根 README 合一（对外版式＋tests 事实句），docs/ 归档"。
> **挂起条件（真冲突才停）**：仅当项目要求对外版**不得含**这些事实句（干净门面硬要求）时——
> 收口单**立牌挂用户**在 A（改 tests 断言基准路径）／B（基准留根、接受门面受损）间拍板，
> **未拍板不放行**（查做分离：这个决策不在执行者职权内——现场裁完踩红实案）。
> 两条判据相容性自查：单条判据过审不等于整套判据可执行。

### D. assets（项目自备）

| 件 | 级别 | 要点 |
|---|---|---|
| `assets/brand/` | 条件 | 项目图标：项目自备（多规格＋矢量源更佳）；没有则写 N/A＋原因，不许拿占位图充数 |
| `assets/team/` | 条件 | 贡献者头像：项目自备；没有则 N/A＋原因 |
| `assets/截图/` | 必选 | 真机截图：测试靶现场、用户名打码、无误触字符、IP 注明对端、附 README 表＋指纹。**CLI 类项目**＝真实运行输出的渲染图视同截图（真跑、未修饰、未补字——真机实测反馈补） |
| `assets/流程图/` | 条件 | **由工程文件制作方提供**（成品图或流程 MD）——发布包制作人不承担重新设计
      （设计意图里的隐晦边界只有工程方知道）；制作方只给 MD 时发布方可代画，
      **成品必须回工程方过目（设计意图校验）**；**有 SVG 源时须与 PNG 同步**（源里藏旧词=翻车点）；只有 PNG、无 SVG 源时在 N/A 立牌专节登记，不伪造源文件 |

## §2 素材（项目自备）

本 skill 不随包任何**给被发布项目用的**图片素材。图标、头像、截图、流程图一律项目自备，按项目实际放 `assets/`；介绍本 skill 自身的图除外。
素材是项目自己的资产，版本随项目走；本 skill 只规定"哪些件必须有、缺了怎么写 N/A"。

## §3 缺件处置

- 缺"条件件"：只在 **FINGERPRINTS.md** 的 `## 条件件 N/A 立牌` 专节逐件写 `- **\`件名\`**：N/A（原因）`；件名与清单逐字一致，目录尾斜杠保留。机器只认这一专节，CHANGELOG 散文、别的章节、相似子串都不算；
- 缺"分发 zip"：应用类照发版规则必打；skill/仓库克隆类可在同一专节写 `- **分发 zip**：N/A（整包克隆即分发形态）`，未登记仍 FAIL；
- 缺其他"必选件"：**不进收口，写 N/A 也不能豁免**——回来补齐再过闸；
- 拿不准算哪级：默认按必选处理，宁可多做。
