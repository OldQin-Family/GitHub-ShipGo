# 分册②附 · README 美化模板（通用版式骨架）

> 对应分册② §4。**美化的本质＝呈现层整形器**：只动版式不动正文，逐行校验兜底。
> 参考实现：第一代 README 美化模板（2026-11-03 实战全过）。
> **⚠ 该第一代参考只是参考形态——现行通用版（`scripts/restyle_readme.py`）与 `en_acceptance_check.py` 必须
> 同包成套分发（restyle 从 en_check 单一真源 import 豁免表；单独跑 restyle 会 `ModuleNotFoundError`，摔响符合设计意图）
> ——照旧参考抄独立件的人会得到一个没有 en_check 的 restyle**。
> 本册把它抽象成通用骨架：七段形态＋变量表＋十步变换＋三条硬纪律。

## §1 七段标准形态（与分册② §1 一一对应）

| 段 | 骨架形态 | 变量 |
|---|---|---|
| ① 标题区 | `<p align="center"><img src="icon.png" width="96" alt="<项目中文>·<项目标记>"></p>` → 语言切换行 → 徽章条 | icon 路径、alt 文案、徽章五枚 |
| ② 开头的话 | 版本引用块 → 开头的话（你为什么做这个项目，引用块，可选）→ 一句话定位（加粗收口句） | 版本号、定位句 |
| ③ 界面一览 | `## 界面一览` ＋ `<p align="center">` 包 `<img width="900">`＋`<sub>图注</sub>`，多图连排 | 截图相对路径、alt、图注 |
| ④ 流程图 | 同上形态，PNG 主图；有 SVG 源时嵌链接（`<a href="...svg"><img src="...png">`），无源在 N/A 立牌专节说明 | 流程图路径 |
| ⑤ 技术板块 | `## 本文目录`（自动生成）→ `## N. 标题` 二级编号章节 | 章节内容（冻结不动的正文） |
| ⑥ 贡献者墙（可选） | 名册列表 → 头像 `<img width="96">` 居中分组 → `<sub>名</sub>` 行 | 头像路径、分组、名册文案 |
| ⑦ 收尾 | 项目站点链接行 → 居中署名行 | 站点地址、署名文案 |

**徽章条标准形**：`<p align="center"><code>MIT License</code> &nbsp;·&nbsp; <code>...</code>...</p>`
——五枚左右，每枚一个事实（License/语言/平台/形态/核心红线摘要）；**徽章一律不带写死的数字**
（单测数/识别率——行数写死必炸）。

## §2 变量表（换项目只改这些）

| 变量 | 说明 | 通用示例（示例项目） |
|---|---|---|
| `ICON_ALT` | icon 的 alt | `ExampleProject 图标` |
| `BADGES` | 徽章五枚文案 | `MIT/Python/Windows/零三方依赖/只绑 127.0.0.1` |
| `SHOTS` | 截图（路径,alt,图注）×N | `assets/截图/main.png`＋两张详情 |
| `FLOW` | 流程图（png,svg） | `assets/流程图/flow.png`＋`flow.svg` |
| `AVATAR_DIR` | 头像目录 | `assets/team/avatar-` |
| `TOC_INSERT_BEFORE` | 目录插入锚（**填提级后的标题**——编号章节已从 ### 提到 ##，锚要与提级后的标题对上） | `## 设计初衷` |
| `SECTION_TITLES` | 章节标题表（守卫/verify 按此配置识别章节，不认中文字面串——本地化项目改这里即可，改标题不改脚本） | `{"screenshots":"界面一览","toc":"本文目录","flow":"整机流程图"}` |
| `WALL` | 折叠墙（可选） | 七条 ⚠️ 警告墙 / N/A |
| `SITE_LINE` | 收尾网站行 | `ExampleProject 的一个本地小工具` |

**config 真实 JSON 键名对照**（真机实测反馈补——左列是概念名，脚本 config.json 吃的是右列真名，**照概念名写必错**）：

| 概念名 | config.json 真实键名 | JSON 形态示例 |
|---|---|---|
| `ICON_ALT` | `icon.alt`（路径是 `icon.src`） | `"icon": {"src": "icon.png", "alt": "ExampleProject 图标"}` |
| `BADGES` | `badges`（字符串数组） | `"badges": ["MIT", "Python 3.10+", "Windows"]` |
| `SHOTS` | `screenshots`（对象数组） | `"screenshots": [{"src": "assets/截图/main.png", "alt": "主界面", "caption": "主界面"}]` |
| `FLOW` | `flow` | `"flow": {"png": "assets/流程图/flow.png", "svg": "assets/流程图/flow.svg"}"` |
| `AVATAR_DIR` | `avatar_dir` | `"avatar_dir": "assets/team/avatar-"` |
| `TOC_INSERT_BEFORE` | `toc_insert_before` | `"toc_insert_before": "## 设计初衷"` |
| `SECTION_TITLES` | `section_titles` | 同上表值 |
| `SITE_LINE` | `site_line` | `"site_line": {"url": "https://example.com", "name": "ExampleProject", "text": "来自 "}` |

> 表中为键值片段，写入 config 时放在同一个外层 JSON 对象里；`site_line.text` 可省略，省略即不加前缀。

## §3 十步变换（幂等管道，顺序固定——与脚本 STEPS 逐一对表）

每步带**已应用守卫**（命中即跳过——可重复执行），每步带**锚文本必中**（找不到就报错中止，绝不静默跳过）：

1. `step_header`：icon 打头（icon→语言行→徽章条；无语言行显式降级放文件顶）；
2. `step_promote_numbered`：编号章节提级（### N. → ## N.，**必须在目录步之前**；无三级编号则 N/A）；
3. `step_screenshots`：插入"界面一览"（守卫：已有则跳）；
4. `step_flow`：流程图插"界面一览"**整节之后**（下一二级标题前，段序=截图→流程图）；
5. `step_toc`：按 GitHub slugger 规则生成"本文目录"（**复刻 github-slugger 规则**：小写、留 L/M/N/Pc、
   空格转 `-`、删标点与 emoji、重名加 -1/-2——此函数两度写错的历史教训：验收不采信自报，须独立实现复算）；
6. `step_wall`：警告墙折 `<details>`（可选步）；
7. `step_avatars`：贡献者头像**行级**统一 96px（只动含头像标记的行、认任意原宽度——非头像行不动）；
8. `step_site_line`：收尾网站行（幂等守卫）；
9. `step_anchor_audit`：**只报告不改写**——页内链接与 slug 配不上的列出来标"自报待验"，
   验收由独立实现（node github-slugger / GitHub 线上点击）给出；自动改写锚点已被实证会造死链；
10. `step_blank_runs`：连续 3+ 空行压成一个。

> 畸形表转引用是某些项目的特有步，通用版 N/A 不进管道。

## §4 四条硬纪律（一字不减）

1. **正文逐字完整性（双向校验）**：原文每一行必须逐字出现在新版里，只允许**四类**例外——
   ①白名单内的畸形表转引用（词序不变）②头像行只改 width ③纯空行压缩 ④编号章节提级只动 `#` 数量
   （norm_level，与代码 verify 白名单一致）。
   任何别的行消失＝正文被动过＝**直接判失败**（脚本 verify 段自动逐行比对）；
   **反向也一样**：新版不得多出原文没有的**整节**——
   已本地化的 README 再跑一次，中文三节重复注入、页内链接 1→10，而旧 verify 只查"原文行少没少"
   查不出"多插的节"。verify 口径＝**双向**：原文行不少＋新版无多插节（章节标题按 §2 `SECTION_TITLES`
   配置识别，不认中文字面串）。
2. **锚点修复只许动 `](#...)` 内部**，行内其余文字逐字一致——比对时把锚目标抹平成 `(#X)` 再对；
3. **自报数不作数**：正文校验、锚点审计的结果都要独立实现复算；脚本只输出"待验清单"；
4. **输入错误必须说人话**：config 顶层必须是对象，实际消费的键按类型校验；`--check` 除正文与多插节外，还必须确认配置要求的标准版式已存在，未整形文件不得假绿。

## §5 通用版脚本

`scripts/restyle_readme.py`（通用版 v2，已实测）：变量从 `-c config.json` 读（§2 变量表），
不传 config 按内置默认。用法：`python restyle_readme.py README.md -c config.json -o README.new.md`
（**`--check` 与 `-o` 不能同用**：`--check` 只校验、不写文件；要校验就对本脚本的输出另跑一次 `--check`，它会同时检查正文、多插节与应有标准版式是否齐全）。

**幂等一键复核**：`python -B -I -X utf8 scripts/restyle_readme.py README.md -c config.json -o README.new.md --idempotent`
——对输出再跑一遍，二次 diff≠0 即 FAIL（专治"重复注入/链接增殖"类盲区）。

> ⚠️ **第一代参考版绑死了某个项目的段落**，直接在别的项目上跑会报"锚文本缺失"中止
> ——别拿它直接跑；真正可复用的是它的 `gh_slug()` 锚点算法（与 github-slugger@2.0.0
> 对拍 66 标题零误差），通用版已内置。

**实测记录（某项目双形态）**：
- 工作副本输入（zip 内版，无语言行/无母节）：3 项显式降级全部明示，被删改行 0，锚点 12/12 配上，exit 0；
- 幂等验证：对输出再跑 `--check` exit 0——可重复执行不变形。

**能力边界（重要）**：版式器**不生成正文内容**——
- 贡献者墙的名册文案与头像行要在**内容阶段**（分册② §1 第 6 段写作时）就写进 README；
  版式器只把已有头像行统一 96px（`step_avatars`），输入里没有贡献者墙时它不报错也不补写；
- **config 的职责分工**：**版式参数**（注入锚 toc_insert_before、章节标题表 section_titles、头像宽度）写 config；
  **`badges`（徽章文案）与 `screenshots[].caption`（图注）属注入内容**——脚本会把它们**注入正文**，
  这不算"改原文"（verify 只查原文行零删改＋节注入按四格判），**但注入后必须重跑英文验收（A3/A4）
  与口径三律自查**——注入的字也要过对外口径；
- **内容先冻结再动版式**的纪律不变：版式跑完若再改内容（含 config 注入值），改完重跑整链。
- **英文版另备英文 config**：`section_titles`/`badges`/`caption` 全英文；
  对英文文档跑中文 config 会触发 restyle 语言混杂降级警告＋en_check A4 CJK 残留 FAIL（分层设防见分册② §4）。

**验收动作**（每次跑完必做）：
- stderr 三行结论：被删改行 0 / 显式降级清单（如有） / 锚点审计数；
- `--check` exit 0；
- **幂等连验**：对输出**再完整跑一遍 restyle**（不是只跑 --check），
  二次输出与一次输出 diff 必须为零——**`--check` 会红**：重复注入（同名节 >1）与未配置注入的节都计入 FAIL
  （实案：已本地化文件再跑，中文三节重复注入、链接 1→10，现版 `--check` 直接判红）；本地化/换标题的项目**必跑此步**
  （或直接加 `--idempotent`，脚本代跑此步——它专治二次输出漂移）；
- 渲染抽查：GitHub/Gitee 网页或本地预览，目录可点、图片加载、贡献者墙居中。
