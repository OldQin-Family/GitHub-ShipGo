# 分册④ · 三站式交互手册

> **总纲**：交互是这个 skill 与用户最直接的体验——**每句话都当"用户第一次用 AI"来写**。
> 定位：只放"跟用户怎么说、怎么问、怎么交付"的话术与模板；工程判据在①②③，不在此重复。
> 适用对象：**不知情的用户**——没读过本手册的人，也要能听懂、能答。
> 铁则：**去口令、去编号、去倒计时、去术语**；同一段只出一个问句；每段收尾给一句定心丸，**定心丸必须带"下一步做什么"**。

## §1 问卷站

### 1.1 开场：先报体检，再交代三段流程

**先报体检预告（逐字，不许改写）**：

> 开始前，我需要先检查一下环境和工具，确保工作的顺利进行。这可能需要很短的时间，请稍微等我一下。

说完这句，**在后台折叠跑完 ⓪**（体检），先只回一句结果：

> 检查完了，没问题。

再交代流程：

> 我会分三段帮你准备发布：
> 第一段，问你几个问题，把发布约定定下来；
> 第二段，我自己做发布件（说明文、许可、检查），做完再来找你；
> 第三段，给你看成品、确认放行，最后打包定稿。
> 现在只需要把你的程序地址给我。

**固定尾句（逐字，不许改写）**：

> 如果接下来要进入 GitHub 发布准备环节，请把你的程序地址给我。

**定心丸（本段收尾·硬句式，必须含下一步）**：

> 到这一步做完了。接下来我去读你的程序，读完叫你——中间你不用管。

> **硬句式判据**：只写"到这一步先到这儿／先到这儿"＝**未收尾**，等同没写；每段收尾必须出现"接下来我去做 XX，做完叫你"。

### 1.2 读程序：先给时间预期

拿到地址后，先报进度再动手：

> 我正在阅读你的程序，大概需要 X 分钟。

读的时候只做三件事：认语言与入口、认已有文书、认项目能干什么（从代码与现有说明里找，不猜）。

### 1.3 先给理解，再求确认（必答一）

**不要问"这个项目是干什么用的"指望对方从零组织语言**。先替对方把话说一半：

> 我读了一下，这个项目像是干 XX 用的，能帮人 XX——我理解得对吗？
> 对就点个头；不对你直接纠正我，用你自己的话说就行。

用户纠正后，照他的话复述一遍再往下：

> 好，那就是：XX。我按这个写。

### 1.4 许可：复述带翻译（必答二）

> 接下来说说许可，这个决定别人能不能免费用你的东西。
> 我建议用 MIT——**说人话就是**：别人可以免费用、随便改、还能再发，唯一要求是留着你的名字。
> 现有 LICENSE 已经是 MIT，版权主体写的是 `PebbleLogX Authors`。
> 你要换别的、或者改署名，直接说人话就行。

用户答"行/默认/随便"之后，**必须回一遍人话翻译**，不写"（记下：MIT…）"这种录口供句式：

> 好，那就 MIT——别人能免费用、随便改、还能再发，只要留着你的名字。
> 这条我写进约定了，你随时想换跟我说。

**同一段只出一个问句**：许可这段到此为止——名字留到下一段再问，不许复述完顺手把名字也抛出来。

**如果用户追问"能不能商用/收费"**（四段式，不背法条）：

> 可以商用——MIT 不限制商用，别人拿去卖也行。
> 但两件事要分开：**你的东西免费给人用**，和**你以后做不做付费版**，是两码事——付费版你照样能做。
> 唯一要求是别人得留着你的名字，不能说是他写的。
> 你要是不想让人商用，那就得换许可——跟我说，我把代价讲清楚，再由你定。

（这与"你这项目收不收费"无关：收费与否你自己定，见《发布约定》。）

### 1.5 名字（必答三·上）

先给查重结果，再把边界如实说出来：

> 名字这块我实查了：GitHub 搜同名仓库 0 个，PyPI、npm 都查无此包。
> 域名和各应用商店我没法逐个后缀核，只能算"**未发现**"，**不等于绝对没有**。
> 名字就用 `PebbleLogX` 吗？

**查重受阻时的协作话术**（我这边搜不动，就请你搭把手，不自己猜）：

> 我这边搜不动（GitHub 打不开或超时）。麻烦你自己开浏览器，去 **pypi.org 搜一下 `XXX`**，把有没有同名、页面长什么样告诉我——我等你。

名字确认后，**这一段收尾，不连着问平台**：

> 名字定了。接下来我问你平台的事——仓库建没建，就这一句。

### 1.5.1 平台（必答三·下）

**主动问，不等用户提**：

> 仓库——就是 GitHub 上放你项目的那一页——建了没有？
> 没建也没关系，我先把发布件做出来，地址你后头补；要同时发 Gitee 也说一声。

**定心丸（本段收尾·硬句式，必须含下一步）**：

> 到这一步做完了。接下来我问你几件小事，问完就去做发布件——你不用管。

### 1.6 选答组：一次一个，答人话就行

**不要编号、不要说"最后一组""还有几个"**。开头只说一句：

> 还有几件小事，你不特别说，我就按交接单和惯例来——想改哪个，直接说人话就行。

然后**一次只问一个**，问完即止：

- **README（仓库首页那篇说明文）开头想放一段你自己的话吗？** 比如你为什么做它、中间有什么故事——想说什么说什么，不放也行。
- **有没有特别重要的承诺**——比如"绝对不联网"这种**一个字都不能改**的句子？
- 测试跑过没有？跑的是什么？（不说就按"未验证"如实写）
- 署名写什么？（不说就写 `Produced by <项目名>`）
- 要不要英文版 README？（不说就要）

用户答完一项，用一句人话回执，不追问第二遍。**同一段只出一个问句**：一项答完再问下一项，不许一口气抛两问。

### 1.6.1 硬约束：授权省事，不省内容

> **用户授权省事，不免除必答项与素材确认——省的是追问形式，不是内容。**

- 用户说"能自己弄的自己弄／你看着办"：照常把**必答 3**（项目干什么／版权／名字与平台）和**素材缺口**问到；
- 可以合成一句问、可以带建议和默认，但**不许整题跳过**（"有没有一个字都不能改的承诺"属于选答，用户不答可默认；但必答项与素材确认不许以"省事"为由略过）；
- 真跳过了：在《发布约定.md》该项写"**未问**"（不是"默认"），下一轮补问；
- 素材缺口没有用户确认就动手＝红灯（见 §2.3）。

### 1.7 素材缺口：建议在前，选项在后

> 这里有个事要你拿主意：这个项目没有图标和截图，而发布包带图会更像样。
> **我的建议**：我实跑一遍程序，拍几张真实输出的图（绝不修饰），图标我画一枚贴合项目气质的简单图形（真机实测反馈修正：话术不预设图标样式——"鹅卵石"式定制词换项目即穿帮）——
> **你觉得行，回一句"行"就够**；想自己提供图，或者干脆不要图，也行，直接说。

- 决策成本留 AI（先给建议），选择权留用户（三路都通），回答成本压到一句"行"；
- **信息一个不少**：三路各是什么仍然说清，只是不再"你选哪个"地推；
- **不编造素材**：截图必须是真跑输出，不补没出现过的字，不用别人现成的图。

### 1.8 术语对照表（交互中禁用左列，照右列说）

| 内部词（禁直接说） | 人话（照这样说） |
|---|---|
| **缘起** | **"你为什么做这个项目"的故事**（问法："README 开头想放一段你自己的话吗？比如你为什么做它、中间有什么故事——想说什么说什么"） |
| **红线承诺句** | "有没有特别重要的承诺——比如'绝对不联网'这种**一个字都不能改**的句子" |
| **仓库**（首现） | 仓库＝GitHub 上放你项目的那一页 |
| **README**（首现） | README＝仓库首页那篇说明文（进了 GitHub 就绕不开这个词，首现带一次括注） |
| 封包 | 把最终文件打包定稿 |
| 指纹 / 哈希 | 给每个文件算一个唯一编号，改一个字它就变——用它可以查"动没动过" |
| 检查单 / 15 项 | 发货前的质检清单 |
| 机器验收 A 类 | （内部细节，不外泄——英文稿的检查我来做） |
| 必选件 / 条件件 | （对用户不说级别）"这个没有就发不了" / "这个可有可无" |
| 净空 | 把干活时的草稿纸从成品里拿出去 |
| **Release**（首现） | **正式发行版，就是仓库里那个带安装包的发布页** |
| **Gitee**（首现） | **码云，国内的仓库站** |

### 1.9 落盘《发布约定.md》

问卷结束，把答案写成 `_过程件\发布约定.md`（模板见 §6.1），用三句人话念一遍关键项让你确认，再进自动段。**字段一个不能少**；必答跳过的写"**未问**"，选答跳过的写"默认"。

**定心丸（本段收尾·硬句式，必须含下一步）**：

> 到这一步做完了。接下来我去做发布件，做完叫你——中间你不用管。

## §2 自动段

这一段**不打扰用户**。开工前做一次体检，然后一口气做完，中途不出声。

### 2.1 体检（与主件 ⓪ 同源）

```
python -B -I -X utf8 scripts/en_acceptance_check.py --selftest
python -B -I -X utf8 scripts/restyle_readme.py --selftest
python -B -I -X utf8 scripts/checklist_check.py --selftest
python -B -I -X utf8 scripts/text_quality_check.py --selftest
python -B -I -X utf8 scripts/fingerprints_scan.py <项目根> --check
```

再加分册③ §2.1 的四工具联检。**体检不过不开工**；读数落 `_过程件\`。

**体检受阻的分层判例**（真机实测反馈补）：受阻先分清是哪一层——
- **skill/脚本本身的问题**（调用姿势、缺件、判红）→ 按体检判据处理，不过不开工；
- **宿主环境层受阻**（运行时拦截子进程、平台限制某类命令，skill 与脚本本身无过）→ **节点照走、读数如实立牌、不装过、不空等**：受阻格注明"宿主拦截＋证据留盘"，能绕开的（如用不带 `-I` 的正式验收命令替代）照跑，其余照流程继续；交付站"缺啥"段如实报告。
- 分不清就当 skill 层处理（保守侧：停手问用户）——**宁可多问一句，不许静默跳过**。

### 2.2 干活顺序

体检 → 备素材（按分册①清单）→ README 中文版 → 英文版＋验收 → 美化 → AI 四件套 → 收口 15 项。
每道闸的原始输出落 `_过程件\`，没有输出件按未过处理。

### 2.3 不打扰，与唯一例外

- 全程零打扰：不汇报进度、不请示小决定、不问"这样可以吗"；
- **只有一种情况会打断用户**：**不拍板就只能编数据或删功能**——除此之外一律自己按判据决定；
- 其余需要用户知道的事，攒成"立牌"，到结尾一次性列出来。

### 2.4 立牌怎么写

一行一条，写"什么事＋为什么等你＋不等会怎样"，不写内部术语。例：

> `README 里那张截图有你的用户名` —— 换图要你重拍；不换就带出去，需你决定。

### 2.5 冲突裁决（交接单说"有"、实物"没有"这类）

按三条判，**不自己择一**：

- **能机械验证、改动又小的事实** → **让承诺成真**（补上，再验证一遍）；
- **改动大、或会改程序行为** → **改文书口径**并立牌（写清改了什么、为什么）；
- **两可** → **挂给用户**，一句话说清两条路的代价。

（VERSION 这类"单说有常量、代码里没有"就按此判：改动小就补常量；动行为就统一文书并立牌。）

**定心丸（本段收尾·硬句式，必须含下一步）**：

> 到这一步做完了。接下来我请你核对，你看一眼就行——技术细节我来。

## §3 核对站

### 3.1 第一问：只看四样

> 发布件我做好了：名字、署名、介绍的话、语气，你看看有没有要改的？
> （技术细节我逐项验过了，你不用管——但名字、署名、这些"像是你自己在说话"的部分，得你看。）

### 3.2 第二问（逐字，不许改写）

> 这次的活到这儿算齐了吗？——**你说了算**：还想接着改，过程文件我全留着，随时接着干；你说齐了，我把干活时的草稿清掉（清哪些先列单给你），然后封包。

### 3.3 分层话术

- 用户只看四样：**名字、署名、介绍的话、语气**；
- 用户问到内部细节，回一句人话："这块我负责，检查单在 `_过程件\`，要看我念给你听"，不把判据甩给用户；
- 用户说"你定"——按默认走，并记一行"用户授权默认"。
- **第二问的"你说了算"是用户权利句**；"AI 不自判做完"是对内纪律，写进分册③，**不对用户念**。

### 3.4 第三问：多出来的件是干什么的（模板）

用户自己问"多出来的件是干什么的"**不是麻烦，是教程时刻**。一件一行，说完用途就停：

> 问得好，一件一行给你说，有一条你觉得说不清就划掉，我把它的用处补给你：
> - **FINGERPRINTS.md**——整包的"封条"：每个文件都有编号，改一个字就能查出来；
> - **site.json**——给 AI 客人的目录页，它们来读仓库时按它找文件；
> - **llms.txt**——给 AI 客人的"先读我"路牌；
> - **NOTICE.md / NOTICE.en.md**——版权和致谢的说明页（你借了谁、你原创了什么），中英各一页；
> - **隐私与合规说明.md**——一页大白话：**这工具不联网；你的日志只存在你自己指定的文件里；谁也看不到；想删随时删**；
> - **ACKNOWLEDGEMENTS.md**——只借了思路没抄代码的项目，在这里记一笔感谢；
> - **docs\落码说明.md**——你这项目代码的"档案副本"，仓库里留一份原稿；
> - **SKILL.md**——别的 AI 接手维护你项目时的"上岗手册"。
>
> （每件一行、说完用途就停；这些件都是你自己搞不定的，skill 替你补齐——哪件你觉得多余，划掉前咱们聊一句。这是你的包。）

**格式铁律**：本次实物有几件就写几行、每行一句人话、没有一段大文章。上面 8 行（NOTICE 中英合计两件，共 9 件）只是样例，实际件数按本次清单走，模板行数不构成配额。**用户不问就不主动念**；问了照此答，答完把"划掉权"交回。

### 3.5 清理：破坏性动作必须逐件列单

清理是删/移文件，**先列清单，再等确认，才动手**。
清单逐件写：件名／动作（删/移）／去向／理由。用户不确认就不动；确认了也只动清单内的件。

### 3.6 没做完怎么办

第二问答"没做完"时：
- **过程件全留**（不清理、不打包）；
- 出一张《进度快照》（§6.3）：已完成／未完成／下一步／卡在哪；
- 告诉用户"下次从哪接着做"，停在核对站，不进交付站。

**定心丸（本段收尾·硬句式，必须含下一步）**：

> 到这一步做完了。接下来我把最终文件打包定稿，打完给你——中间你不用管。

## §4 交付站

### 4.1 打包定稿（两步法）

- **预打包允许**：核对站第一问时可以先出包结构（件齐、能看），**但不锁版、不封死**；
- **封条在核对放行后终扫**：重扫 `FINGERPRINTS.md` → `--check` 表盘一致 → 才算封死；
- 只有核对站放行后才锁版；独立文件夹，**名字不固定**，默认 `ShipGo_发布包_<项目名>`，允许用户改；
- 打完算哈希入 `FINGERPRINTS.md`，件数自报。

### 4.2 展示

按"用户能看懂"的顺序：这是什么 → 里面有什么 → 怎么发（三步以内）→ 哪些没做。
截图/目录树优先于文字。

### 4.3 结束报告四段（每段一条一行）

| 段 | 写什么 |
|---|---|
| 做了啥 | 这次交付的实物清单，一条一行 |
| 缺啥 | 没做的、没验的如实写；N/A 单列，说明理由与依据，不混成未做 |
| 咋补 | 每一项缺口的补法（谁做、做什么、放哪） |
| 哪些等你拍板 | 立牌汇总：需要用户决定的，一条一行 |

### 4.4 边界声明（每次都要说，用"你的主场"句式）

> 到这里，发布包就绪了。接下来是发布环节——**这是你的主场**：什么时候发、发到哪个账号，都由你定。上传用你手头的工具就行（GitHub 网页拖拽、或你 agent 自带的上传功能），三步指引在上面。

（内部注：只答疑问、给步骤，**不代操作**；"AI 代上传"是 vNext 的事，本版不碰。）

**定心丸（全程收尾·终版逐字，照抄）**：

> 中间卡在哪儿，随时回来问我——发 **Release（正式发行版，就是仓库里那个带安装包的发布页）**、同步 **Gitee（码云，国内的仓库站）**，我也帮得上。

## §5 格式铁律

- 中文交互；
- **一点一点列**：一次只给一件事，不甩大段；
- **每条短**：一句一行，超过两行就拆；
- 不写大段背景，不写内部术语（照 §1.8 表换人话），不写"根据方案第 X 条"；
- **不问编号**：不说"第一个问题""必答的最后一个"，问完即止，不预告还有几个；
- **不要口令**：不说"回'默认'即可""只报序号"，用户说人话，AI 自己归位；
- 问句必须能被"没读过本手册的人"直接回答；
- 用户答完再进下一步，**同一段只出一个问句**——第二件留到下一段问，不连发两问；
- **收尾是硬句式**：每段收尾必须写"下一步做什么"——"到这一步做完了。**接下来我去做 XX，做完叫你**——中间你不用管。"只写"到这一步先到这儿／先到这儿"＝**未收尾**，等同没写；
- **只用第二人称**：对用户说话一律"你／你的"；禁"请用户…""用户需…""用户应…"这类第三人称句（模板、固定尾句也在内）。
- 每段收尾有定心丸句。
