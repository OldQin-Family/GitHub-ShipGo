## §1 README 版式七段（固定，顺序不动）

1. **标题区**：居中 icon＋项目名＋双语切换行＋徽章行（License/平台/语言/形态/红线摘要）；
2. **开头的话**：版本行＋一句话定位。**用户想放自己的话就放这里**（版式上叫"开头的话（你为什么做这个项目）"，引用块，说人话，不带厂商名；
   末句落到"产品回答什么问题"——好句式是"它只回答谁在什么时候做了什么"这类可验收的具体问题）；
3. **界面一览**：真机截图（**必有**，没有截图不发版——造现场也要拍）＋图注；
4. **整机流程图**：中英双版 PNG 主图；有 SVG 源时随包并与 PNG 同步，无 SVG 源在 FINGERPRINTS 的 N/A 立牌专节说明，不伪造源文件；
5. **技术内容板块**（好几点，用编号小节）：范围/运行/自测/数据格式/实现细节/边界与漏检/许可——
   技术细节放开写，**口径三律照样管**；
6. **贡献者墙（可选）**：名册列表＋头像居中排版＋一句项目自定的致谢语。
   **"照抄"是可验收判据**：交接单/委托方明示"文案照抄"的内容**逐字保留**，
   验收＝与委托原文逐字 diff 零差异——自主简化、改写、精炼一律判"偏离任务单"
   （实测实案：把每人一句话简化成岗位名，被判必修）。
   **英文版贡献者墙口径**：中文版照抄判据**不跨语言**——
   英文版＝人名用拼音（名册权威在中文版）＋一句话岗位按原意翻译（不是逐字机械转）＋
   头像与中文版同一套；处置在 FINGERPRINTS 立牌一句"英文贡献者墙按分册② §1 第 6 条口径意译"；
7. **收尾**：项目站点链接＋自定署名行（署名文案由项目定，默认 `Produced by <项目>`）。

> **素材里出现厂商名/敏感信息**：默认**换素材**（重截图/重画图）；
> 确实不可换（如真机系统界面无法避开）时**保留＋图注立牌说明**＋FINGERPRINTS 登记——
> 不许静默发布，也不许因一张图挂整条发布线（挂发布是极端情况，需用户拍板）。
> **真机截图"换/留"判例**：
> **必须换**＝画面含**真实用户名/真实用户路径/内网 IP**（身份与拓扑暴露）；
> **可留（图注立牌）**＝第三方进程名（如任务栏/托盘里的其他软件名）、公网对端地址（通信对端非本机拓扑）、
> 系统自带 UI 元素——这类属"环境内容"非素材敏感信息，**图注说明来源与边界＋FINGERPRINTS 登记即可**；
> 判据相容性自查：本判例与主判（默认换）不冲突——主判管"素材本身含敏感"，判例管"画面里出现的第三方环境内容"。

### §2.1 环境预检（**第⓪步·阻断式**）

**缘起**：失败记录进上下文＝负面样本；连续环境类失败（stdout 被吞/shell 错认/编码/引号）
→生成分布偏移→卡循环/兔子洞。开工前先摸清环境＝把环境事实提前变成正面样本
（实测卡点分类：环境类占大头）。

**预检摸的不只运行环境，还有随行工具自身**：
**四个脚本各跑一遍 `--selftest`：`en_acceptance_check.py`、`restyle_readme.py`、`checklist_check.py`、`text_quality_check.py`**；
**探针 `fingerprints_scan.py` 没有 `--selftest` 这个开关（照抄必报错）——它走 `--check` 对实物目录校验，
其行为自检由四工具联检 `selftest_4tools` 承载（分册③ §2.1）**。
预检吐的"调用方式"**以实测为准**（探针打印 `sys.executable` 实测路径，不假设 `python` 在 PATH——
实案：python 不在 PATH 而预检吐"python <脚本>"，照抄必挂）。
**阻断式**：⓪不过不开工——环境事实没进上下文之前，站一一个字都不写。

**复制跑这一段即可**（stdlib，不联网，退出码恒 0）：

```python
# env_probe —— 环境预检：每条输出＝事实＋可复用的操作指令（调用方式为实测，非假设）
import sys, tempfile, os
print("[python]", f"{sys.version_info.major}.{sys.version_info.minor} @ {sys.executable}",
      f"→ 调用方式：\"{sys.executable}\" <脚本>   （本机实测路径，python 可能不在 PATH——实案：exit 49）")
shell = "PowerShell/CMD 族" if sys.platform.startswith("win") else "POSIX shell 族"
print("[shell]", f"platform={sys.platform}，族={shell}",
      "→ 多行脚本一律落 .py/.ps1 文件再执行，不拼内联引号（引号冲突高频翻车）")
try:
    with tempfile.NamedTemporaryFile("w", encoding="utf-8", delete=False) as fh:
        fh.write("probe-ok"); tmp = fh.name
    ok = open(tmp, encoding="utf-8").read() == "probe-ok"; os.remove(tmp)
    print("[写文件]", "可写已验证（tempfile 通道）",
          "→ 用 python open(path,'w',encoding='utf-8') 写文件；不要用 shell heredoc 拼正文（反引号/转义会被吃）")
except OSError as e:
    print("[写文件]", f"不可写：{e}", "→ 换有写权限的环境或请委托人授权")
print("[stdout]", f"encoding={sys.stdout.encoding or '?'}",
      "→ 输出为空/乱码时：落文件再读（python xxx.py > out.txt 2>&1），别反复重试回显")
print("[网络]", "本段不联网",
      "→ 查重/联网受阻时：声明假设＋记录方法＋复搜时机留档，不静默跳过（分册① §0 兜底）")
print("预检完成：带着上面各条『→』开工。下一步＝四脚本 --selftest＋selftest_4tools 嵌码联检（探针无 --selftest、走 --check；开发期副本可带 --dev-archive——留档格显式开关，不带＝留档格不跑；成品位不加）。")
```

> 主件第⓪步已挂"环境预检（阻断式）"＋"四脚本 --selftest＋嵌码联检"两项；执行者（尤其弱模型）
> 开工先跑这段，环境事实提前进上下文＝失败螺旋从源头不启动。

## §3 中英双版流程（自动段③）——一出一验

1. **中文内容版定稿**（版式七段齐＋口径三律自检过）；
2. **中文版检查**（技术外部分：语气说人话/无超前账/缘起段不涉厂商名）；
3. **出英文稿**（一次）：任一模型或人译皆可，**输入必带三样**——
   ① 中文定稿（冻结后再译，译文不许反过来改中文）② 术语对照表（§3.1）③ 禁用清单（§3.2）；
4. **英文验收**（一次，对 §3.3 清单逐条勾，**不是"再润一遍"**）：
   机器项脚本跑（exit 0）＋人判项逐条签＋任一项不过**定点改那一处重跑机器项**，不整篇重润；
5. **落《英文验收单》**（§3.4 模板）随发布件留档；
6. NOTICE/致谢类文件**最好同步英文版**（读者不一定是国人）。

### §3.1 术语对照表（每项目一份，发版前定；先定表再译）

每行 `中文 ｜ 英文定译 ｜ 禁用旧译`，至少覆盖五类：核心名词（如台账=ledger；白名单**统一选一个**，
不许两个都出现）/红线词（零端口=no listening ports 等）/版本事实（`v0.1.8 has no query subcommand`——
**不能省 no**）/产品名（大小写固定）/命令（v/n/e/t/c/q 原样不译）。
术语禁用旧译只是验收的一项，不是全部；完整机器验收一键入口见 §3.3（锚点、链接、术语与 CJK 都要过）。
   **四条格式纪律**：①**定译本身不进禁用列表**——只禁旧译，把定译塞进
   禁用列＝整篇误报（实案：定译自禁）；②**禁用旧译不得与代码字面量冲突**
   （如禁 whitelist 时代码里真有 whitelist.json 文件名）——冲突时降级为"正文概念禁用、字面量豁免"
   并写进术语表备注；③术语表格式＝`{"定译": ["禁用旧译", ...]}`，键=定译、**值必须是字符串数组**
   （值写成字符串会被 extend 按字符拆成单字母，整张验收单作废——
   脚本对非数组值报错、对 `_` 前缀键跳过＝备注键不进校验）；④**字面量豁免显式结构**：
   `{"定译": {"ban": ["旧译"], "allow_literals": ["代码里合法的该词"]}}`——纯 grep 逼人改正确正文
   （实案：`zero connections` 是内部状态名，跟红线旧译不是同一概念，脚本分不清）。

### §3.2 禁用清单（跨项目通用）

- **AI 腔**：把显而易见的事讲成发现、抖机灵收尾、无意义加粗、三段式排比、em dash 连发；
- **超前账**：把"规划中"写成"已有"；把"没有"写成"支持"；
- **红线稀释**：`zero dependencies` 这类听着好但不准的话——有第三方运行时依赖（含可选依赖）就写 `minimal runtime dependencies`，并按项目实际列清；
- **擅自扩写**：中文没写的论断英文不许自己加（原句尤其不许补漂亮结尾）；
- **中文残留指引**：`see the Chinese README`、`待补`、`形式对齐初稿`。

### §3.3 英文验收清单

**A 类·机器跑（exit 0 才算过）**——**一键入口：`python -B -I -X utf8 scripts/en_acceptance_check.py README.en.md --terms terms.json --dir 项目根`**，输出验收单 A 类段落直接可粘（首跑即逮住 zero ports 旧译的实案）。
**A 类只 A1-A4**：
A1 目录锚点全可点（gh_slug 对拍 github-slugger）；A2 本地链接/图片逐个查盘；
A3 术语表禁用旧译零命中（grep）；A4 禁用词/中文残留零命中（含 CJK 残留检测）。
**A5 红线句对照不在 A 类**——"红线句与中文定稿逐字对照"归入 C 类人判（见下）。
**B 类·人判（逐条签）**：①事实与真码一致；②口径三律；③出声读一遍说人话；
④核心边界（如"只读的过去≠实时的现在"）英文没被润没了。
**C 类·中英对表（人判）**：A5 红线句/规划句/版本事实逐句对照（分册③第 11 项届时只复核）。
     **A5 英文侧过判据**：英文版"逐字对照"物理不成立（中文全角标点带不过去），
     过判据＝**①红线承诺逐项语义对齐（每条承诺在英文版有对应句且无弱化）＋②terms 定译词在对应句命中**——
     两条齐＝PASS，随验收单留对照表（自签法转正为官方判据）。

## §4 美化（自动段④，内容冻结后）

- 美化＝**只动版式**：diff 内容必须为零（加粗/居中/图片嵌入允许，文字变更不允许）；
- **首跑语义**：干净 README 首跑 restyle
  **应 exit 0**——管道注入的标准节（目录/截图/流程图）属预期注入，记显式降级声明、不判 FAIL；
  **"首跑 exit 1 属预期"是旧码的绕行口径，已作废**（执行者基于旧码的
  绕行经验不得直接采纳进判据，以修后代码语义为准）。首跑后的验收顺序：出件→覆盖→对**生成后的文件**跑 `--check` exit 0
  →幂等连验 diff 0；`--check` 同时正向确认配置要求的目录/截图/流程图/icon 已存在，未整形文件与标准节被删会判红；
- **一键幂等复核**：`python -B -I -X utf8 scripts/restyle_readme.py README.md -c config.json -o README.new.md --idempotent`
  ——对输出再跑一遍，二次 diff≠0 即 FAIL（**`--check` 会红**：重复注入与未配置注入的节都计入 FAIL；`--idempotent` 专治二次输出漂移）；
- **通用版式骨架与整形脚本**：见《分册②附_美化模板.md》＋`scripts/restyle_readme.py`；
- **英文版美化须另备英文 config**：
  `section_titles`/`badges`/`caption` **全英文**；restyle 对
  "英文文档＋中文注入值"会记**显式降级警告**（非阻断；中文判定与 en_check 同一张豁免表——单一真源）；
  en_check A4 含 **CJK 残留检测**（中文进英文版＝FAIL，豁免口径＝allow_literals＋代码块/行内代码＋
  **资源目标路径**（markdown `](…)`／HTML `src="…"`/`href="…"`——分册① assets/截图/ 等中文目录名是
  册子自定的，同源）＋语言切换锚/署名预置豁免）——三层合闸，单修一道留两道；
- **`site_line.text` 缺省＝空前缀（中性）**，不会自动塞中文；需要“更多小工具：”这类前缀时，中英文各自在 config 显式写 `text`，英文版配英文前缀（A4 会抓残留中文）；
- 参考实现（第一代）：一个真实项目的 README 美化 1.3（专用版，实战全过）；
- 美化后**重新走一遍 §3 的检查**——版式操作可能把链接/图片路径弄断。

## §5 AI 四件套（自动段⑤）

| 件 | 是什么 | 硬判据 |
|---|---|---|
| `SKILL.md` | AI 运行时手册 | 何时用/铁律/最短路径/排雷/隐私话术；命令与代码真码一致。

| README 给 AI 的说明（AI-friendly section） | 给 AI 的指路 | 四原则＋怎么问 AI＋行为边界＋相关文件表 |

- **四件互验**：同一事实（版本号/命令表/字段表/红线）四处必须一致；
- **零超前账**：query 式规划命令只在"没有，规划中"语境出现；
- **给 AI 的说明**是**每个项目的必答题**：不做"可选"，做多少写多少但必须有。

## §6 口径三律（全册压着）

1. 每句要么"已实现事实"要么挂牌"vNext 规划中"——**没实现的当已实现写＝头号翻车**；
2. 不写厂商名、不写真实用户路径；样例统一 RFC 5737（192.0.2.0/24、example.com）与 `C:\Program Files\Example\`；
3. 红线/承诺句（零端口、零外连、不采音频…）**逐字保留**——美化也不许动。
4. **源材料同样过口径扫描**：源材料（工作副本/交接单）内部可能
   自相矛盾（实案：工作副本开头"不写厂商名"正文却写了具体厂商名）——矛盾时**按对外口径处理并立牌**；
   实测三种处置（照抄/中英不一致/主动泛化）证明这条必须显式写，执行者才有所适从。
